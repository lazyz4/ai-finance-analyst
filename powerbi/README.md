# Power BI 看板搭建说明

目标：把 SQL 层已经算好的口径做成四页看板，并用 DAX 把规则判定重新实现一遍，与 SQL 结果逐行对账。

做完之后可以说：同一套口径在 Excel 底稿、SQL 视图、DAX 度量值里各实现一次，22 项指标判定结果完全一致。

预计 30-45 分钟。全程不需要写表关系、不需要在 Power Query 里做透视、也不需要手工新建几十个度量值。

---

## 第 1 步　生成数据表

回到项目根目录执行：

```bash
python analysis/export_for_powerbi.py
```

`powerbi/tables/` 下会生成 6 个 CSV。做看板只需要其中 3 个：

| 文件 | 行数 | 作用 |
| --- | --- | --- |
| 年度透视.csv | 1 | 一行宽表，26 列，含两期的全部科目金额 |
| 指标监测.csv | 22 | 22 项指标的规则、阈值、监测值与判定结果（字段已拍平，不需要建关系） |
| 季度明细.csv | 16 | 季度趋势图的数据源 |

`财务明细.csv`、`规则.csv`、`指标状态.csv` 是给你对照检查用的，看板不需要导入。

---

## 第 2 步　导入三张表

Power BI Desktop → **主页 → 获取数据 → 文本/CSV** → 选择文件 → 右下角点 **加载**（不是「转换数据」）。

重复三次，依次导入 `年度透视.csv`、`指标监测.csv`、`季度明细.csv`。

导入后右侧「数据」窗格里会出现三张表，表名就是文件名（年度透视、指标监测、季度明细）。**每个文件只能导入一次**，如果出现「年度透视 (2)」这样的表名，删掉多余的那张，否则后面的 DAX 会找不到表。

> 想展示 Power Query 能力的话，可以不导入 `年度透视.csv`，改为导入 `财务明细.csv`，再用 `queries.m` 里的「查询 2」做透视。结果表结构与 `年度透视.csv` 完全相同。这只是加分项，不影响看板效果。

---

## 第 3 步　不需要建关系

这一步是空的，故意如此。

通常做法是导入一张规则表再和指标表建关系。这里把规则字段（方向、关注阈值、预警阈值、规则说明、判定结果）直接拍平进了 `指标监测` 表，所以矩阵按 `指标监测[item]` 逐行显示时，度量值用 `SELECTEDVALUE` 就能取到对应阈值与方向。

少一层关系，就少一类「关系基数配错导致数字全错」的问题。

---

## 第 4 步　一次写入全部度量值

1. 左侧视图栏点 **DAX 查询视图**；
2. 打开 `measures_model_update.dax`，把全部内容复制进去，覆盖编辑区的默认内容；
3. 点工具栏的 **更新模型**（Update model）；
4. 切回 **报表视图**，右侧「数据」窗格里 `年度透视`、`指标监测`、`季度明细` 三张表下面就会出现这 59 个度量值。

比逐个手工新建快得多，也不容易抄错括号。

如果「更新模型」不可用或报错（旧版本没有这个功能），退路是逐个新建：打开 `measures.dax`，按六个分区一条条复制，名称写在等号左边。

**数字格式是可选的美化**，不影响计算。建议只给下面这几类设置：

| 度量值 | 格式 |
| --- | --- |
| 营业总收入、净利润、经营活动现金流净额 | 千分位，0 位小数 |
| 各种「同比」「率」 | 百分比，1 位小数 |
| 四个 变化_百分点 | 小数，2 位小数，后缀 ` pp` |
| 三个周转天数、现金转换周期 | 小数，1 位小数，后缀 ` 天` |
| 现金含量 | 小数，2 位小数，后缀 ` 倍` |
| 监测值_DAX、监测值_SQL、对账_差值 | 小数，2 位小数 |

---

## 第 5 步　四个页面

页面布局见 `layout.svg`，用浏览器打开就能看。建议先建四个空白页并命名，再逐个放视觉对象。

**页面 1　总览**

- 五张 **卡片图**：营业总收入、净利润、经营活动现金流净额、现金含量 2025、现金转换周期 2025
- 一个 **多行文本**（或卡片图）放 `核心矛盾文本`
- 一张 **折线与柱形组合图**：X 轴放 `季度明细[quarter]`，柱形放 `季度营业收入`，折线放 `季度经营活动现金流净额`

**页面 2　盈利质量**

- 一张 **表格**：直接把 16 个盈利质量度量值放进去即可；更清楚的做法是建一张 4 行的辅助表（毛利率、净利率、经营现金流率、三费占收入比）做成矩阵
- 一张 **簇状柱形图**：比较 2025 与 2024 的四个比率
- 多行文本放结论：利润端改善来自净利率与费用率，经营现金流率是唯一触发规则的一项

**页面 3　营运资本与现金质量**

- **簇状柱形图**：应收账款、存货、应付账款周转天数的 2024 与 2025 对比
- 两张卡片：现金转换周期 2025、现金含量 2025
- 多行文本放「方向不一致」的说明

**页面 4　异常清单与对账**

- 三张卡片：`预警数`、`关注数`、`正常数`
- 一张 **表格**：行放 `指标监测[item]`，列依次放 `kind`、`monitor_basis`、`监测值_DAX`、`watch_threshold`、`状态`、`触发规则`、`对账_状态一致`
- 给「状态」列加条件格式：`关注` 琥珀色 `#B45309`，`预警` 红色 `#B91C1C`，`正常` 保持中性灰
- 想只看需要核查的，加一个「状态」筛选器，或按 `对账_状态一致` 筛选

视觉规范：主色 `#1F3B63`，辅助色 `#9DB8D6`，页面背景 `#F4F6FB`，字体统一微软雅黑，标题 14，正文 10-11。不要在页面上放装饰图形。

## 第 6 步　校验对账（别跳过）

这一步是它与普通数据可视化作业的区别，也是面试时最值得讲的一段。

新建一页，放一张表格：

| 放什么 | 期望值 |
| --- | --- |
| `指标监测[item]` 作为行 | 22 行 |
| `监测值_DAX` | 与 `监测值_SQL` 一致 |
| `对账_差值` | 全部为 **0**（允许 0.0001 以内的浮点误差） |
| `对账_状态一致` | 全部显示 **一致** |
| `关注数` | **3** |
| `预警数` | **0** |
| `正常数` | **19** |

如果对不上，按顺序查三处：

1. `年度透视` 是不是只有一行（重复导入会产生多行）；
2. 表名是否被加了 `(2)` 后缀，导致度量值引用了错误的表；
3. 「状态」列上有没有残留筛选器，把部分指标过滤掉了。

## 常见问题

**「更新模型」按钮是灰的？** 确认脚本以 `EVALUATE` 结尾——它必须同时是一条合法的 DAX 查询。`measures_model_update.dax` 结尾已经带了。

**导入后数字变成文本？** 检查 CSV 导入时是否选了 UTF-8。若表头下第一行被识别成文本，Power BI 会整列按文本处理，需要在 Power Query 里把类型改成小数。

**中文表名可以吗？** 可以。DAX 里用单引号包住即可，例如 `'年度透视'[rev_2025]`。

**为什么不直接连 SQLite？** 需要先装 SQLite ODBC 驱动，配置成本高于读 CSV。现在的分工是 SQL 负责口径、Power BI 负责建模与可视化，职责清楚也更好复现。

**卡片图显示成科学计数法？** 在度量值的格式设置里把小数位数设为 0 并打开千分位分隔符。
